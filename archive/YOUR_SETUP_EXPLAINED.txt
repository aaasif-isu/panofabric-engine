================================================================================
WHAT IS FSDP?
================================================================================

FSDP = Fully Sharded Data Parallel

Inside Island 1:
  - Model is too big for one GPU
  - Split model across GPU 0 and GPU 1
  - GPU 0: Layers 1-8 (Shard 1)
  - GPU 1: Layers 9-16 (Shard 2)
  - Both GPUs process SAME batch (8 samples)
  - GPU 0 processes samples 0-3, GPU 1 processes 4-7
  - They sync after each forward pass (FAST - NVLink)
  
Benefit: Use 2 GPUs to fit larger model
Speed: NVLink (fast, local connection)

================================================================================
WHAT IS HELOCO/DILOCO (DECENTRALIZED)?
================================================================================

Trains on EACH ISLAND independently:

Step 1-20:
  Island 1: Train on English data (GPU 0+1)
  Island 2: Train on French data (GPU 2+3)
  Both in PARALLEL - no communication
  
Step 20: SYNCHRONIZATION
  Island 1: "Here are my gradients from English"
  Island 2: "Here are my gradients from French"
  Server: "Combine and update both models"
  Both: Download new model
  
Step 21-40:
  Island 1: Train with updated model on English
  Island 2: Train with updated model on French
  Both in PARALLEL again
  
Advantage: Only communicate every 20 steps, not every step!
          Reduces network overhead significantly

================================================================================
THREE LEVELS OF SYNCHRONIZATION
================================================================================

1. WITHIN GPU (Not applicable - single GPU)
   └─ N/A

2. WITHIN ISLAND (GPU 0 ↔ GPU 1 or GPU 2 ↔ GPU 3)
   └─ FSDP: After each forward/backward pass
   └─ Speed: FAST (NVLink)
   └─ Every step

3. BETWEEN ISLANDS (Island 1 ↔ Island 2 ↔ Server)
   └─ HeLoCo/DiLoCo: After sync_steps (every 20 steps)
   └─ Speed: SLOW (Ethernet)
   └─ Only every 20 steps (not 20 times per step!)

================================================================================
COMMUNICATION EFFICIENCY
================================================================================

CENTRALIZED APPROACH (standard):
  Every step: Send gradients to server
  100 steps = 100 communications
  Network utilization: 100x
  
DECENTRALIZED APPROACH (HeLoCo/DiLoCo/MLA):
  Every 20 steps: Send gradients to server  
  100 steps = 5 communications
  Network utilization: 5x
  
REDUCTION: 95% less network traffic! ✅
TRADE-OFF: Slight staleness (islands use slightly outdated weights)
           But often negligible with proper sync_steps tuning

================================================================================
QUICK Q&A
================================================================================

Q: Does each island run on separate machines?
A: No, both islands on same machine (4 GPUs total)
   In production, islands would be on different machines

Q: Do GPU 0 and GPU 1 always have the same data?
A: Yes, within island they process same batch (different samples)
   But Island 1 sees English, Island 2 sees French

Q: Is synchronization automatic?
A: Yes, handled by HeLoCo/DiLoCo/MLA middleware
   You don't need to code it

Q: Can I change sync_steps?
A: Yes! Adjust sync_steps in heloco.yaml
   Smaller = more communication (slower)
   Larger = less communication but more stale (bad convergence)
   Default 20 is usually good

Q: Why 2 islands if I have 4 GPUs?
A: Flexibility! You could do:
   - 1 island × 4 GPUs (pure FSDP, no decentralized sync)
   - 2 islands × 2 GPUs (recommended, tests decentralized learning)
   - 4 islands × 1 GPU each (simulate multi-machine)

Q: What's non_iid data?
A: Non-Independent-Identical-Distribution
   Island 1 sees English only
   Island 2 sees French only
   More realistic federated learning scenario
   (vs IID: all islands see same language)
